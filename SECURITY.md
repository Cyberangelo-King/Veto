# Security Policy

Veto is an experimental hackathon prototype for simulated fraud decision support, not a live banking or card service.

Do not publish exploitable details in a public issue. Contact the repository owner privately through GitHub's private vulnerability-reporting channel if enabled; otherwise use an established private maintainer channel. Reports should include affected component, prerequisites, reproducible steps using synthetic data, impact, and mitigation if known. Never include live secrets, full card numbers, or private customer records.

Expectations: no real payment credentials/data in fixtures, logs, screenshots, or demos; treat merchant/transaction text as untrusted; authorize every state-changing operation server-side; require explicit confirmation; keep secrets out of source; and state limitations honestly.

During the hackathon, only the active submission candidate is expected to receive fixes. No production support or service-level commitment is implied.
